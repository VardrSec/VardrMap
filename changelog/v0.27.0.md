# v0.27.0 — 2026-08-15

## Evidence, redacted on write

Evidence is the most dangerous data this platform holds. A captured request that
proves a vulnerability usually also contains the credential used to reach it —
and that credential belongs to someone else's production system, in a document
read by more people than the engagement team.

### Redaction happens on write, never on render

`redaction.py` is the single place secrets are stripped, and it runs before the
row is stored. Redacting in the serializer instead would mean one forgotten path
— a log line, an export, a debug endpoint, an error message — leaks it. **What is
never stored cannot leak from a path nobody remembered.**

Removed: sensitive header values (`Authorization`, `Proxy-Authorization`,
`Cookie`, `Set-Cookie`, `X-API-Key`, …), sensitive body and query keys
(`password`, `token`, `access_token`, `client_secret`, `api_key`, …),
credentials embedded in URLs, bare JWTs recognised by shape, and
`Bearer`/`Basic` tokens appearing in prose. Organizations can add their own keys.

### Structure survives on purpose

`Authorization: Bearer [REDACTED]` still proves the request was authenticated,
which is frequently the entire point of the evidence. Replacing the whole line
would destroy the finding it supports. `Cookie: a=1; b=2` loses the **whole**
value rather than having each pair matched individually and mostly surviving.
Non-sensitive fields stay — which identity was used is often the finding.

### The Evidence entity

Kinds: `http_request`, `http_response`, `terminal_output`, `tool_result`,
`note`, `screenshot`. Each item carries `collector`, `source`, `sensitivity`
(`public`/`internal`/`confidential`/`restricted`, CHECK-constrained on Postgres)
and `retention` (`engagement`/`90d`/`permanent`).

`content_hash` is SHA-256 over the **stored** body — integrity of the artefact
as retained, not as captured, which is the only thing we can honestly attest to.

Bodies are capped at 200,000 characters so a pasted response cannot exhaust the
row or the response.
