# v0.19.5 — VardrRunner extracted to its own repository

**Date:** 2026-06-13

VardrRunner (the local CLI that runs tools on the operator's machine and uploads results)
has been split out of this monorepo into its own repository,
[jorge-aquino/VardrRunner](https://github.com/jorge-aquino/VardrRunner), with full commit
history preserved via `git subtree split`. There was zero code coupling between the runner
and the backend — they only ever communicated over the HTTP API — so this is a structural
change with **no runtime impact**: the `/jobs/*`, `/runner/heartbeat`, `/runner/status`,
and import endpoints are unchanged, and the runner integrates exactly as before.

## Removed

- `runner/` directory (Python CLI package + its 113 tests). It now lives in the VardrRunner
  repo and is installed from there.
- The `runner` job from `.github/workflows/ci.yml` (the runner's tests run in its own CI now).
- The `/runner` pip entry from `.github/dependabot.yml`.

## Changed

- Docs repointed at the new repo instead of the in-repo directory:
  - `CLAUDE.md` — "Where things live" + verification sections (Runner block removed; link out).
  - `README.md` — VardrRunner described as its own repo; roadmap item marked done.
  - `docs/development.md` — "VardrRunner Setup" trimmed to a connection guide + links to the
    VardrRunner repo's README/docs (single source of truth for install/CLI/daemon/tools).
  - `docs/architecture.md` — product table + VardrRunner section now describe the **integration
    contract** (how the runner consumes VardrMap's API); runner internals link to the new repo.
  - `docs/roadmap.md` — extraction item checked off; Dependabot item no longer lists `runner/`.

## Notes

- What stays in VardrMap: the backend endpoints the runner calls, the `runner_heartbeats`
  table, the `runner`-scoped API key type, and `backend/tests/test_runner_heartbeat.py`
  (which tests those endpoints, not runner code).
- No endpoint, model, or env-var changes. Documentation/structure only.
