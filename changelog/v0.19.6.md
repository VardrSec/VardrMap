# v0.19.6 — Runner-scoped service uploads, settings improvements, React key fix

**Date:** 2026-06-20

## Changed

- **Services scope split** — `POST /programs/{id}/services` now accepts runner-scoped API keys so
  VardrRunner can upload nmap results without a full-access key. `GET` and `DELETE` still require
  full scope. Updated `docs/api.md` with scope requirements.

- **Settings: scope badge and last-used date** — Active API keys in the Settings section now show
  a scope badge (`full` / `runner`) and a "Last used" date alongside the creation date. The data
  was already present in `ApiKey` and returned by the backend; it just wasn't displayed.

- **Submissions: React key moved to Fragment** — The submissions table map was wrapping each pair
  of rows (`<tr>` + edit-row `<tr>`) in an unkeyed `<>` shorthand fragment, causing React list
  warnings. Changed to `<Fragment key={s.id}>`.

- **Docs: sidebar section count corrected** — `docs/architecture.md` said 7 top-level sections;
  the `Section` type union has had 8 values since the Submissions section was added in v0.19.0.
  Added the missing Submissions row to the navigation table and updated the count and description.

## Fixed

- `SubmissionsSection` — eliminated React list-key warning on the submissions table.

## Tests

- `backend/tests/test_services.py` — added `TestRunnerScopeServices` with three cases:
  runner key can POST, cannot GET (403), cannot DELETE (403).
