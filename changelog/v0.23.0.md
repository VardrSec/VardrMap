# v0.23.0 — 2026-08-09

## Remove the Submissions tracker

**Breaking. This migration deletes data.**

Submissions recorded reports filed to HackerOne and Bugcrowd, and the payout each
one earned. That is bounty hunting. VardrMap is a penetration testing platform,
where the deliverable is a report to a client — not a submission to a platform's
bounty queue, and not a payout to total up.

The whole feature is gone: the nav section, the API, the model, the schemas, the
tests, the docs, and the table.

### Removed

- **Frontend** — the `Submissions` nav entry and `SubmissionsSection`, the
  `Submission` and `SubmissionPrefill` types, `submissionPrefill` state, the
  `PROMOTE_TO_SUBMISSION` / `SUBMISSION_PREFILL_CONSUMED` actions, and
  `promoteToSubmission` from `AppContext`. `Section` is now 7 values, not 8.
- **Cross-section entry points** — "Log Submission →" on a finding and
  "Submit →" on a report. Findings still promote to reports; reports still
  export.
- **Backend** — `routers/submissions.py`, the `Submission` model, the
  `SubmissionCreate` / `SubmissionUpdate` schemas, and the `SubmissionStatus`
  literal that carried `paid`.
- **API** — all four `/engagements/{id}/submissions` routes. `GET
  /engagements/{id}/stats` no longer returns `submissions_count` or
  `submissions_by_status`; every other key is unchanged.

### Migration `0015_drop_submissions`

Drops the `submissions` table on the next deploy. **Every submission row is
permanently deleted.** The data has no equivalent under the engagement model, so
nothing is migrated. `downgrade()` recreates the table structure but cannot
restore the rows — that needs a database backup.

### Copy changes

Reports is now "Draft **client-ready** reports from validated findings" (was
"submission-ready"), and the Overview quick action reads "Draft a **client**
report".

### Not changed

**Target Radar** still shows `max_payout` for the programmes it lists. Radar
surfaces real bug bounty programmes on HackerOne and Bugcrowd — payout range is
accurate information about an external programme, and `RadarProgram` is
explicitly out of scope for engagement renaming.
