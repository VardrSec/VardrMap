# v0.37.0 — katana and gau

**Date:** 2026-10-08

Two discovery tools join the job queue and the import endpoint. Runs need VardrRunner
v0.38.0 or later, which installs and executes them; nothing changes for existing tools.

## katana — crawler

Crawls target URLs on their root domain and records every endpoint it finds as recon.

- Job type `katana`, from `scope` or `recon`. Config: `depth` (1–10), `js_crawl`
  (`true`/`false`; also parse JavaScript files for endpoints), `limit` (1–1000000),
  `status_code`, `timeout` (1–86400 s).
- Import type `katana`. Accepts VardrRunner's compact records and katana's own JSONL, so a
  file exported straight from katana can be imported by hand. katana writes full raw
  responses on every line; **response bodies are never read or stored**.
- Recon rows get URL, host, path, status, length, and content type. Request method is not
  stored: recon has no method column, and recon is de-duplicated by URL.

## gau — archived URLs

Passive. Asks public archives (Wayback Machine, Common Crawl, AlienVault OTX, urlscan) which
URLs they have recorded under each wildcard scope domain. Nothing is sent to the target.

- Job type `gau`, from `scope` (its wildcard entries, like subfinder). Config: `subs`
  (`true`/`false`, default on), `providers` (any of `wayback`, `commoncrawl`, `otx`,
  `urlscan`, as a comma string or list), `timeout` (1–86400 s).
- Import type `gau`, `{"url": ...}` per line.

## Shared behaviour

- **Queue-time validation** matches VardrRunner: out-of-range depth, a non-boolean
  `js_crawl`/`subs`, an unknown provider, or an unknown key returns `400` before the job is
  stored, rather than failing on the operator's machine after it is claimed.
- Only `http`/`https` URLs become recon. Archives routinely contain `mailto:`, `javascript:`,
  and malformed entries.
- katana and gau are separate recon sources, so the same URL found by both appears once per
  source.
- Composer entries: katana (depth, limit, *Parse JavaScript* toggle, off by default) and gau
  (*Include subdomains* toggle, on by default, matching the runner; providers). Both are also
  in the manual import dropdowns.

## Fixed

URL-shaped recon imports (ffuf, and now katana and gau) checked new rows only against rows
already stored, so a URL repeated **within one upload** was stored twice. Duplicates inside
an upload are now dropped too. This also makes VardrRunner's chunked uploads of large
results safe to send in pieces.

## Tests

Backend: 824 tests (20 new) — job acceptance, every rejected config, cross-user `404` for
jobs and imports, compact and raw katana imports (no bodies stored), gau URL filtering, de-
duplication within and across uploads, separate sources, and HTML stripping. Frontend: 111
tests (3 new), pinning the composer keys and toggle defaults to what the backend accepts and
the runner assumes.
