# v0.22.1 — 2026-08-09

## Drop the bounty stat row from the engagement Dashboard

The Dashboard header carried a four-tile row — **Recon assets**, **Findings**,
**Accepted**, **Paid** — directly beneath the section title. Two of those tiles
counted bug bounty submission outcomes, and one of them reported how many reports
had been *paid out*. That framing belongs to bounty hunting, not to the
professional testing engagements VardrMap is now built around.

The whole row is removed. The severity breakdown chips below it are unchanged,
so the Dashboard still surfaces finding counts by severity at a glance.

### Also removed

`DashboardSection`'s local `Stats` type declared six fields but rendered only
two. `recon_count`, `scans_count`, `submissions_count`, and
`submissions_by_status` are gone; the type now describes just the
`findings_count` and `findings_by_severity` the component actually reads. The
`/engagements/{id}/stats` endpoint is unchanged and still returns the full set.

### Not changed

- **Target Radar's `max_payout` display** (`OverviewSection`). Radar lists real
  bug bounty programmes on HackerOne and Bugcrowd — payout ranges are accurate,
  in-domain information about those external programmes, and `RadarProgram` is
  explicitly out of scope for engagement renaming.
- **The Submissions section.** It remains a bug bounty submission tracker,
  payout column and all. Reframing or retiring it is a product decision, not a
  label change, and is tracked separately.
