# v0.18.0 — Scheduled Scans, Notifications, Multi-Runner, Radar Tracking

**Date:** 2026-06-12

## What's new

### Scheduled scans

Recurring scan definitions — "run httpx on my scope daily" without re-queueing by hand.

- `scheduled_scans` table + CRUD at `/programs/{id}/schedules` (tool, source, config, interval: hourly/daily/weekly)
- **No backend cron**: due schedules are materialized into pending jobs inside `GET /jobs/pending` — the runner's poll (or daemon) drives the clock, so schedules fire exactly when a runner is around to execute them
- `next_run_at` advances from now, so a runner offline for a week creates one catch-up job, not seven
- Composer gains a Recurrence picker (once/hourly/daily/weekly); recurring specs create schedules instead of jobs
- New Recurring Scans panel under the Composer: pause/resume toggle, next-run countdown, delete

### Webhook notifications

- `users.webhook_url` + `users.notify_min_severity`; new `GET/PATCH /settings` endpoints
- Fires on: scan job failure (operator cancels excluded) and nuclei imports containing findings at/above the threshold
- Payload includes both `content` (Discord) and `text` (Slack) so either webhook style works unconfigured
- Sent via FastAPI BackgroundTasks — webhook latency never delays an API response
- SSRF guard: HTTPS only; localhost, private, link-local, and `.internal` targets rejected
- Settings UI: webhook URL field + severity threshold picker in the Settings section

### Multi-runner support

- `runner_heartbeats` unique key changed from `owner_github_id` to `(owner_github_id, hostname)` — a laptop and an always-on VPS now report independently instead of overwriting each other
- `GET /runner/status` returns a `runners` array (per-machine online state, tools, last seen); top-level fields mirror the most recent runner for backward compatibility; `online` is true if any runner is online
- Bridge shows a per-machine list when more than one runner has reported

### Radar → Program tracking

- "+ Track" button on each Target Radar entry creates a program (name, platform, URL pre-filled), selects it, and jumps to Scope

## Fixed

- Rate limiter is now disabled under pytest (`ENV=test`) — the suite shares one client IP and was tripping the global 200/min limit as it grew
