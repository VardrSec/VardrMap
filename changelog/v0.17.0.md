# v0.17.0 — VardrRunner Daemon

**Date:** 2026-06-12

## What's new

### VardrRunner daemon (`vardrrunner daemon`)

A long-running background worker that replaces the manual `vardrrunner jobs run` workflow.

**Commands:**

```bash
# Run in the foreground (Ctrl+C to stop)
vardrrunner daemon start

# Detach to background — PID written to ~/.vardrrunner.pid, logs to ~/.vardrrunner.log
vardrrunner daemon start --detach

# Custom intervals (seconds)
vardrrunner daemon start --poll-interval 10 --heartbeat-interval 30

# Log to a specific file
vardrrunner daemon start --detach --log-file /var/log/vardrrunner.log

# Check status
vardrrunner daemon status

# Stop a background daemon
vardrrunner daemon stop
```

**Behavior:**

- Polls `/jobs/pending` every 5 s (configurable via `--poll-interval`).
- Sends heartbeats every 60 s on a dedicated background thread — heartbeats continue even while a long-running job (nuclei scan, nmap) is executing.
- Graceful shutdown: SIGINT/SIGTERM finishes the current job before exiting and removes the PID file.
- `--detach` re-launches the daemon as a separate process (`start_new_session=True`) and exits immediately, leaving the child running in the background.
- Transient API or network errors are caught and logged; the daemon continues polling.

**Internal refactor:**

- `run_jobs()` in `commands/jobs.py` now delegates the execution loop to the new public `execute_pending_jobs(client, console, yes)` function. Both `vardrrunner jobs run` (one-shot) and `vardrrunner daemon start` (continuous) share the same job execution path.
