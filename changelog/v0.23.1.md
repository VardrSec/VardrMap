# v0.23.1 — 2026-08-09

## Cleanup after the Submissions removal, and correct docs that misled setup

### The `NEXTAUTH_URL` trap

`docs/development.md`, `frontend/.env.example`, and `frontend/README.md` all
listed **`NEXTAUTH_URL`** as a required frontend variable. That is the Auth.js
**v4** name. This app runs v5, which reads `AUTH_SECRET` / `AUTH_GITHUB_ID` /
`AUTH_GITHUB_SECRET` and never reads `NEXTAUTH_URL` at all.

Anyone configuring a fresh Vercel project from those docs would set a variable
nothing consumes and get a login failure with no obvious cause. All three now
document `AUTH_URL` as optional — Auth.js v5 infers the app URL from the
incoming request and uses `VERCEL_URL` on Vercel, so it only needs setting
behind a host-rewriting proxy.

### AI triage prompt

`routers/findings.py` opened its suggestion prompt with *"You are a bug bounty
triage assistant."* That framing reached users on every AI-assisted finding, in
the model's own output. It now reads *"You are a penetration testing
assistant."*

### Leftovers from v0.23.0

- `frontend/test-utils/renderWithApp.tsx` still mocked `promoteToSubmission`,
  a context value that no longer exists. `npm run typecheck` could not catch it:
  the harness casts through `as unknown as AppContextValue`, which defeats
  excess-property checking. Noted in `CLAUDE.md` so the gap is known.
- `docs/roadmap.md` had an open task naming `SubmissionsSection`.

### Stale migration chain

`docs/development.md` listed the Alembic chain ending at `0011rbacreconscopes`
— four revisions behind. It now runs through `0015dropsubmissions` and uses the
real revision ids rather than filenames.

### Dead override removed

`overrides.sharp` in `frontend/package.json` is gone. It was added in v0.19.1 to
force sharp past a vulnerable range when `next` declared `^0.34.5`. next 16.3.0
(v0.23.0, via #29) declares `^0.35.3` itself, making the override a no-op.
Verified after removal: sharp still resolves to 0.35.3 and `npm audit` reports 0
vulnerabilities.

`overrides.postcss` stays — next pins postcss to exactly `8.5.23`, so the
override is still what dedupes it against `@tailwindcss/postcss`'s `^8.5.16`.

### `CLAUDE.md` rewritten around the pentest model

The charter led with "professional security testing platform for penetration
testing and bug bounty work" and described the product as *transitioning*. That
is no longer accurate — the transition happened. It now states plainly that the
unit of work is an engagement performed for a client under a written
authorization, that features are designed for the pentest case first, and that
bounty framing (payouts, accepted/paid outcomes, platform-submission language)
should not be introduced into new UI copy, prompts, or models. Target Radar is
called out as the one place bounty vocabulary is correct, because it describes
external programmes.

Also refreshed: test counts (464 backend, 63 frontend), the 7-value `Section`
union, `npm run typecheck` in the verification steps with a note on the
`renderWithApp` blind spot, the Auth.js v5 variable names, and a new hard rule
requiring explicit sign-off before a destructive migration.
