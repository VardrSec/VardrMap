# v0.28.0 — 2026-08-15

## Authorization, job-state and redaction defects found in review

**Breaking: scope rules no longer imply subdomains.** See the migration note below.

An external review of v0.24–v0.27 reproduced seven defects. All are fixed, each
with a regression test. The suite was green throughout because these cases were
simply absent — a passing suite is evidence about the tests that exist, not
about the ones that do not.

### 1. Scope matching could authorize out-of-scope targets

Three separate bypasses in `policy.py`:

- **Path prefix.** A rule for `/v1/admin` authorized `/v1/administrator` —
  `startswith` let a longer sibling name inherit a shorter rule's authorization.
  Matching now stops at path segment boundaries.
- **Scheme and port ignored.** A rule for `https://host:443/v1` authorized
  `http://host:8080/v1`. A different port is a different listener, frequently a
  different application. Both are now part of a URL rule's identity.
- **Implicit subdomains.** `acme.com` authorized every name beneath it,
  including `internal-admin.acme.com` — a default-allow on the control whose
  entire purpose is default-deny.

**Migration note.** Subdomain coverage now requires an explicit wildcard:
`*.acme.com` for subdomains only, `*acme.com` for apex plus subdomains. Any
engagement relying on the old implicit behaviour must add a wildcard rule, or
its jobs are denied with `target_out_of_scope`. Denying is the safe failure.

Exclusions keep implicit subdomain coverage — excluding `prod.acme.com` still
excludes `db.prod.acme.com`. The asymmetry is deliberate: widening a deny is
safe, widening an allow is not.

### 2. `PATCH /jobs/{id}` bypassed the policy engine

The endpoint set status directly, so a job denied at `/claim` could be PATCHed
to `running` instead. The testing window, stop-work switch and scope rules were
advisory on that path.

Any transition **into** `running` now clears the policy engine. Transitions to
`done`/`failed` deliberately do not — a runner must always be able to report the
outcome of work already performed, including after a stop-work.

### 3. Organization viewers could mutate jobs

The global `/jobs/{id}` endpoints resolved access through
`accessible_engagement_ids`, which answers *can this caller see it*, not *may
they change it*. `PATCH`, `DELETE`, `/claim` and `/events` now all enforce
viewer read-only.

### 4. Redaction missed ordinary secrets

The value pattern excluded spaces and commas, so `{"password": "hunter 2"}` and
`{"api_key": "sk_live_abcd,efgh"}` matched nothing and reached the database
verbatim. Passphrases contain spaces and API keys contain punctuation — these
were ordinary secrets, not exotic ones.

Quoted values now run to their closing quote; bare values run to a structural
delimiter or end of line. Quoted values are matched first so the bare pattern
cannot chew through a placeholder and corrupt the surrounding JSON.

### 5. Asset graph missed the primary ingestion paths

`httpx` imports went through the enrich/upsert path, which never called the
linker, and findings created through the API were never linked at all — the two
richest sources of attack-surface information stayed off the graph. Both now
link, and a finding relinks when its `asset` changes.

### 6. Organization tenancy was incomplete

- Engagements reachable only through an organization did not appear in
  `GET /engagements`; the list queried owned + invited. It now uses the same
  `accessible_engagement_ids` as every other path.
- `my_role` flattened organization roles to `member`, so an admin looked like a
  member and a viewer looked writable — and the UI uses that field to decide
  what to show. It now resolves through `deps.engagement_access`.
- Clients stayed owner-scoped, so a firm could not share one. Now
  organization-scoped, with ownership still honoured for pre-existing rows.

### 7. Migration `0018` never created the foreign keys the ORM declares

Four `asset_id` columns were added as plain strings. Without the constraint the
database enforces nothing and `ON DELETE SET NULL` never fires — deleting an
asset leaves rows pointing at an id that no longer exists, and every join
through it silently returns nothing.

Migration `0020` clears orphaned references, then adds all four constraints.
Postgres only; SQLite cannot `ALTER TABLE ADD CONSTRAINT` and tests build the
schema from the models.

Backend suite: 640 → 670.
