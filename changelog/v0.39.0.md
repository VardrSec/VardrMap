# v0.39.0 — Engagement delivery workflows

**Date:** 2026-10-09

Closes the loop from testing to client deliverable: what each run actually found, a finding's
remediation and retest history, immutable client reports, and reviewed VardrGate case authoring.
Adds migration `0025workflows` (additive; one alembic head). Pairs with VardrRunner v0.41.0.

## Behavior change: `job_id` is now validated

`POST /imports` and `POST /services` accept an optional `job_id`. It used to be stored as a free
string; it is now a real reference and **must be a job of the same engagement**. An unknown id, or
another engagement's job, returns `404` and imports nothing. VardrRunner always sends the id of the
job it is executing, so normal operation is unaffected. Anything that tagged imports with invented
ids must stop doing so. This also closes a gap where a caller could link results to another
engagement's job.

## Execution provenance

`job_result_links` records every recon, scan and service row a job *observed*, not just the rows it
created. Deduplication used to make "what did this run find" unanswerable once a later run
re-observed the same host or URL. `GET .../recon`, `.../scans` and `.../services` filter by
`job_id` through these links. `import_records` gains `job_id`.

## Finding history and retests

Every finding create and update appends an immutable snapshot (the first update of a pre-existing
finding records a `baseline` of its prior state). New `GET/POST .../findings/{id}/activity` records
remediation notes and retest attempts; a retest requires an outcome (`still_open`,
`partially_fixed`, `verified_fixed`, `inconclusive`) and can reference evidence by title and
SHA-256. A verified retest does not change the finding's status. Snapshots and notes are redacted
before storage. A "Remediation & retests" panel appears on each finding; viewers can read but not
write.

## Client reports (deliverables)

`/engagements/{id}/deliverables` builds a client-facing report from the testing record. Every save
is an **immutable revision**: a frozen snapshot of scope, authorizations, selected findings and
evidence, and retest history, with rendered Markdown and its SHA-256. Only `status` changes after
creation. Saves require the `base_revision` they started from and return `409` if it is stale.
Snapshots are redacted and capped at 4 MiB; evidence is rendered as indented blocks so
target-controlled text cannot escape the report. The Reports page can create, revise, set status,
download Markdown and print/save as PDF. This delivers the "client-facing deliverable generation"
roadmap item.

## Reviewed VardrGate case authoring

`POST .../test-cases/preview` drafts cases from selected API Surface operations or an OpenAPI 3.x
document and stores nothing. `POST .../test-cases/reviewed` saves them only with an explicit
`reviewed: true`. Drafts never copy credentials, bodies, examples or security values, never fetch
`$ref`s, and start with every access decision `skip`, since observed responses do not say who
*should* have access. API Surface gains a selection column and a "Draft authorization tests" panel.

## Smaller changes

- `GET .../jobs` gains `status`, `limit`, `offset` and returns `total`; `GET /jobs/{id}/events` gains
  `limit`, `offset` and returns `total`. Omitting `limit` still returns everything, so the job board
  is unchanged.
- `GET .../recon` gains a `source` filter.

## Deploy notes

Migration `0025workflows` only adds: one nullable column with an index and foreign key on
`import_records`, and four new tables. No existing rows are rewritten. Its `downgrade()` drops the
new tables and would delete any history and report revisions created since; export them before
rolling back.

## Tests

Backend 839 tests (the three existing provenance tests now create real jobs, plus two that pin the
rejection of unknown and cross-engagement job ids, and the workflow suite). Frontend 134 tests, 21
of them new, covering the activity panel, case builder and deliverables UI, including the viewer
restrictions and that editing drafts withdraws the review confirmation.
