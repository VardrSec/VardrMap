# v0.19.4 — Backend Observability

**Date:** 2026-06-13

Adds application logging and optional error tracking so production failures are
visible instead of silent. Builds on v0.19.3 (shares `notifications.py`).

## Added

### Structured logging + optional Sentry

- New `logging_config.py` — `configure_logging()` runs at startup (from
  `main.py`) and routes logs to stdout (Railway captures stdout as the service
  log) at a level from `LOG_LEVEL` (default `INFO`; unknown values fall back to
  `INFO`). Application code logs under the `vardrmap.*` namespace.
- Optional Sentry: set `SENTRY_DSN` to report errors to Sentry for aggregation
  and alerting. `sentry-sdk` is listed in `requirements.txt` but only imported
  when a DSN is present, so it stays an optional, inert dependency otherwise.
- New env vars `LOG_LEVEL`, `SENTRY_DSN`, `SENTRY_TRACES_SAMPLE_RATE` — see
  `docs/development.md`.

## Fixed

### Webhook failures are no longer swallowed silently

`send_webhook` previously did `except Exception: return False` with no record,
so a misconfigured or SSRF-blocked webhook was invisible (it runs in a background
task, so the caller never sees the return value). It now logs a warning when a
send is rejected by validation, blocked by the host-resolution guard, or fails
at the HTTP layer, plus a debug line on success.

## Tests

- Backend: 343 tests (was 336). New `test_logging_config.py` covers level
  configuration, unknown-level fallback, idempotency, and both Sentry paths
  (init-with-DSN and missing-SDK) via injected `sys.modules`; a notifications
  test asserts a blocked webhook is logged rather than swallowed.

No endpoint or model changes. The new env vars are all optional.
