# v0.34.1 — Integration hardening

## VardrGate result integrity

- Result uploads now create a per-job receipt. An identical retry returns the original counts without duplicating scan items or evidence; a different second payload returns `409`.
- The stored test case is authoritative. An upload whose `test_case_id` differs from the queued case returns `400` instead of filing results under incorrect provenance.
- Stored cases validate VardrGate's execution-critical rules for unsafe methods, access decisions, denial statuses, resource references, and setup steps.
- Optional body-free `executions[].response_profile` data is preserved in evidence for structural comparison workflows.
- Spec and result limits are measured as serialized UTF-8 bytes, and test-case names/descriptions are sanitized by active Pydantic validators.

## Burp and API Surface

- Canonical operation creation tolerates simultaneous first observations, and observation counts increment atomically.
- Operation and exchange views expose pagination instead of silently hiding records after the API defaults.
- Page-derived statistics are labelled as visible-page values; the operation count uses the API's unpaginated total.
- The Burp extension labels the originating Burp tool, promotes all selected messages, and includes response content type.
- The sidebar hides new-engagement controls while an engagement is active; selecting “Choose an engagement” in the Active Engagement dropdown reveals them again.
