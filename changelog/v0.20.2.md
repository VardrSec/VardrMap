# v0.20.2 — Review tab badges, manual→finding promotion, scope filter, UX hardening

**Date:** 2026-06-20

## Added

- **Review tab live badges** — each Review tab (Recon / Scans / Manual / Services)
  now shows the current item count as a small badge. Counts come from the program
  object already in memory (no extra fetch). The `services_count` field was added
  to `serialize_program` and the frontend `Program` type to complete the set.

- **Manual test → Finding promotion** — each manual test card has a "→ Finding"
  button alongside Edit/Delete. Clicking it prefills the Finding form with the
  test's title, hypothesis (→ summary), payload (→ steps), and evidence (→ impact),
  then navigates to Findings. Closes the last gap in the promotion chain
  (manual → finding → report → submission).

- **In scope only toggle** — Recon and Scans views both gain an "In scope only"
  button in the filter bar when the program has in-scope items defined. Filtering
  is client-side (no API call): recon items match by hostname suffix against scope
  values; scan items match by asset. The panel title updates to reflect the
  filtered count. The toggle is hidden when no scope is defined.

- **confirm() before delete** — `deleteManualTest` now confirms before deleting,
  consistent with the guards added to findings, submissions, and reports in v0.20.1q.

## Fixed (reliability / UX)

- **AbortController on all fetch effects** — `FindingsSection`, `SubmissionsSection`,
  `ReconSection`, and `DashboardSection` now cancel in-flight requests on unmount
  or dependency change, eliminating state-update-on-unmounted-component warnings.

- **Debounced platform filter** — `SubmissionsSection` platform text input now
  waits 400 ms before committing to filter state, so the API is not hit on every
  keystroke.

- **Escape key closes HostDetailPanel** — pressing Escape now closes the slide-over,
  consistent with modal/drawer conventions.

- **FindingsSection loading skeleton** — three pulse-skeleton rows are shown while
  findings load instead of a blank panel.

- **Dashboard uses `/stats` endpoint** — replaced three parallel fetches
  (findings, submissions, recon) with a single `GET /programs/{id}/stats` call.

- **Job board trash icon** — hover-reveal trash button on every job in stream,
  pipeline, and table views, wired to the existing `deleteJob` function.

- **Terminal → Review button** — when a job completes with results, a "→ Review"
  button appears in the Terminal footer and opens the correct Review tab:
  `ffuf/httpx/subfinder → Recon`, `nuclei → Scans`, `nmap → Services`.

- **Double-commit fix** — `jobs.py` and `submissions.py` create endpoints now use
  `db.flush()` before `log_action` so the resource and its audit log row are
  written in a single transaction.

- **N+1 in serialize_program** — replaced five separate `COUNT(*)` queries with
  a single loop, reducing program-list overhead from 5N queries to N.

- **Recon dedup host-only fix** — re-importing a subfinder result set no longer
  silently creates duplicate rows for host-only entries (those with no URL).

- **DB indexes** — Alembic migration 0012 adds `program_id` indexes on `findings`,
  `scan_items`, `manual_tests`, `reports`, and `recon_items`.
