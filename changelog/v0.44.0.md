# v0.44.0 — managed authorization and reconciled user guidance

**Prepared:** 2026-11-11

**Status:** Prepared source version, not a published release. This entry groups
changes already in the source tree; it does not announce a Git tag, GitHub release,
published image, deployment or qualified Community distribution.

## Changes

- Clarify legacy advisory scope checks, enforced managed authorization and
  configured engagement budget controls in the security guide.

- Offer source access on sign-in and Settings. Builds with an explicit complete
  source revision link to that commit; other builds identify the repository.

- Retain the project license in backend and frontend runtime images without
  changing its terms or the existing build contexts.

- Add explicit managed authorization for reviewed Gate jobs, preserving ordinary
  queueing and separately enabled execution.
- Enforce job/runtime binding, finite budgets, concurrency reservations and
  cancellation; uncertain outcomes remain held for original-run reconciliation.
- Add operation/identity/boundary coverage, review-only case drafts and
  operator-approved AI queue proposals.
- Preserve missing or historical provenance as unknown in review and exports.
- Improve approval context, stop-work handling and session-expiry notices.
- Update container security packages and protect agent-local settings.
- Separate public user documentation from private planning and validation notes.
- Reconcile the domain model, setup navigation, API guidance and security model
  with implemented execution ownership, managed authorization and configured
  engagement budgets. Distinguish stop-work requests from confirmed termination.
- Give operators one [Full setup path](https://github.com/VardrSec/VardrSec/blob/main/docs/installation.md)
  and one [Mapless setup path](https://github.com/VardrSec/VardrSec/blob/main/docs/mapless.md),
  separate from component-development instructions.
- Document persistent v3 admission and its reporting boundaries alongside the
  supported finite v1/v2 protocol, without implying platform qualification.

## Compatibility and operational limits

Managed execution remains explicitly enabled and separately authorized. Ordinary
queueing does not confer managed execution authority. Unknown execution outcomes
retain their reservations until reconciliation; stop-work is not proof that a
process has exited. Full and Mapless keep separate identities and state, with no
automatic migration between them.

Follow the installation guide and its current support limits rather than treating
this source version as an upgrade or deployment instruction. Historical notes in
this directory are retained unchanged; their version headings alone do not prove
that matching release artifacts were published.
