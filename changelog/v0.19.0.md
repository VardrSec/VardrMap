# v0.19.0 — RBAC, Recon Dedup, API Key Scopes, Submissions Analytics

**Date:** 2026-06-12

## What's new

### RBAC — Program Membership

Invite GitHub collaborators to a program without sharing your account.

- `program_members` table + CRUD at `/programs/{id}/members` (add/remove/list)
- `GET /programs` now returns both owned programs and programs where the user is an invited member
- Members can read and write all program resources (findings, reports, submissions, jobs, etc.)
- Only the owner can: delete/PATCH the program, manage members
- `get_program_or_404` updated to allow member access — existing BOLA tests unchanged; non-member wrong-user access still returns 404

### Recon diffing + new-asset alerts

Re-importing the same httpx or ffuf scan no longer creates duplicates. New items get `first_seen_at` stamped once and never overwritten.

- Dedup key: `(program_id, source, url)` — exact URL match
- Import response now includes `new_count` and `imported_count` (new items only)
- `recon_items.job_id` — optional link back to the scan job that produced the item
- Webhook fires when `new_count > 0` on an httpx import (if configured)

### API key scopes

Limit what a leaked VardrRunner key can do.

- New `scope` field on API keys: `"full"` (default, unrestricted) or `"runner"` (jobs, imports, heartbeat only)
- Settings UI shows a full/runner toggle when generating a key
- Runner-scoped keys get `403` on all other endpoints; browser JWTs always have full scope
- `GET /auth/apikeys` now returns `scope` for each key

### Submissions analytics panel

- Stats bar gains a 4th stat: **Avg time-to-resolve** (days between `submitted_at` and `resolved_at` for accepted/paid submissions)
- New analytics section under the stats bar (shown when submissions exist):
  - **By Severity** — horizontal bar chart (critical → info)
  - **By Platform** — table with submitted, accepted count, and total payout per platform
