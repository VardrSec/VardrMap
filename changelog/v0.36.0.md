# v0.36.0 — 2026-10-07

## Security — replace python-jose with PyJWT (CVE-2026-85394)

**JWT verification moves from `python-jose` to `PyJWT`.** `python-jose` ≤ 3.5.0 carries **CVE-2026-85394** (CVSS 9.1, critical, **no patched release**): an algorithm-confusion flaw that allows **HS256 token forgery** when a verifier does not strictly pin algorithms. VardrMap already pinned `algorithms=["HS256"]` with audience/issuer checks, but the library itself is unpatched at critical severity, so it has been removed.

- **`backend/deps.py`** — `_resolve_jwt` now decodes with `PyJWT`; token semantics are unchanged (HS256, `aud=vardrmap-backend`, `iss=vardrmap-frontend`, `exp` enforced). All `PyJWTError` subclasses map to `401`, as `JWTError` did before.
- **`backend/requirements.txt`** — `python-jose[cryptography]==3.5.0` → `PyJWT==2.15.1`. This also removes the `ecdsa`, `rsa`, and `pyasn1` transitives that python-jose pulled in.
- **CI** — the backend `pip-audit` step drops the now-obsolete `--ignore-vuln PYSEC-2026-1325` (that advisory was the `ecdsa` timing side-channel, which leaves with python-jose). `pip-audit -r requirements.txt` now passes with no ignores.
- **Tests** — the auth suite's token minting switches to `PyJWT`; all behaviour (missing / empty / garbage / expired / wrong-audience / valid / runner-scoped) is unchanged and passing.

### Impact

No API, token format, or configuration change. Existing browser JWTs and `vmap_` API keys continue to work; `BACKEND_JWT_SECRET` is still the HS256 signing secret. This is a dependency swap for security, not an auth-behaviour change.

## Security — frontend dependency fixes

- **`next` 16.3.0 → 16.4.0** — clears the critical `next/og` ImageResponse RCE advisory plus the SSRF-in-image-optimization and SSG/ISR cache-poisoning advisories. Lint, typecheck, the 108-test suite, and `next build` all pass on 16.4.0.
- **New `overrides`** pin patched transitives that ship in the app: `source-map-js ^1.2.2` (event-loop DoS, high), `dompurify ^3.4.16` (DOM-XSS via jspdf), and `baseline-browser-mapping ^2.11.0` (invalid-input DoS). `npm audit --omit=dev --audit-level=high` now reports **0 production vulnerabilities**.

## CI — frontend audit scoped to production dependencies

The frontend `Dependency audit` step now runs `npm audit --omit=dev --audit-level=high`. Dev/build-only tooling (the `@next/eslint-plugin-next` → `braces` stack-exhaustion chain, the jest/babel chain) carries transitive advisories that are unpatched upstream and never reach the deployed bundle; auditing them as a hard merge gate blocked every PR on advisories no dependency bump could clear. Anything in the production bundle is still gated at high severity.
