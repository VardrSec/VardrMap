# v0.19.9 — Submissions: linked finding picker and row badge

**Date:** 2026-06-20

`finding_id` was already stored on `Submission` and returned by the API but was
never exposed in the UI. Two additions close that gap.

## Changed

- **New submission form** — added a "Linked Finding" select field that loads the
  program's findings (`GET /programs/{id}/findings?limit=200`) lazily on first form
  open. Selecting a finding sends its `id` as `finding_id` in the `POST /submissions`
  body. Pre-filled via `submissionPrefill` as before.

- **Submissions table** — when a row has a non-empty `finding_id`, a small
  `↗ finding` button now appears below the title. Clicking it navigates to the
  Findings section so the user can cross-reference the linked issue.

## Notes

No backend or migration changes — `finding_id` is already persisted and returned.
The field is stored as a plain string reference (no FK constraint), so it degrades
gracefully if the finding is later deleted.
