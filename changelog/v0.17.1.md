# v0.17.1 — Daemon Windows Fixes + Connection Pool Hardening

**Date:** 2026-06-12

## Fixed

### Daemon was broken on Windows (critical)

The v0.17.0 daemon used `os.kill(pid, 0)` as a liveness probe and `os.kill(pid, SIGTERM)` for shutdown. On Windows, `os.kill` is not a signal API — any signal value other than the console events invokes `TerminateProcess`:

- **`vardrrunner daemon status` would kill the running daemon** (the "probe" terminated it with exit code 0).
- **`vardrrunner daemon stop` hard-killed mid-job** — the SIGTERM handler never runs on Windows, so there was no graceful shutdown and the PID file was left stale.
- **`--detach` didn't survive terminal close** — `start_new_session=True` is POSIX-only.

**Fixes:**

- Liveness probe now uses `OpenProcess`/`GetExitCodeProcess` via ctypes on Windows; `os.kill(pid, 0)` is only used on POSIX (where `EPERM` now correctly means "alive").
- Cross-platform graceful shutdown protocol: removing the PID file is the stop signal. The daemon re-checks the PID file every poll cycle and exits after finishing the current job. On POSIX, SIGTERM is still sent so an idle daemon exits immediately.
- `--detach` on Windows now uses `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` so the daemon survives terminal close.
- New guard: starting a second daemon while one is running is refused instead of silently overwriting the PID file.
- The daemon only removes the PID file on exit if it still contains its own PID (avoids clobbering a replacement daemon's file).

### Backend: stale Postgres connections after idle

`create_engine` now passes `pool_pre_ping=True`. Railway closes idle Postgres connections; without the pre-ping, the first request after a quiet period failed with a closed-connection error.

## Tests

- Runner suite: 113 tests (was 104). New coverage: Windows-vs-POSIX probe paths, `EPERM`-means-alive, stop-via-PID-file-removal, double-start guard, stale-PID-file startup, detach creation flags per platform, and a regression test asserting the Windows probe never calls `os.kill`.
