# v0.30.0 — 2026-08-16

## dnsx and naabu are queueable; two named pipelines replace the recon chain

VardrRunner has shipped handlers for `dnsx` and `naabu` for some time. VardrMap's
`_VALID_TOOLS` never accepted them, so the execution side existed and the control
plane refused to dispatch. Both are now first-class tools with config validation,
and the Composer offers two named chains instead of one.

### Pipelines

| Pipeline | Chain | For |
|---|---|---|
| **Attack Surface** | subfinder → dnsx → httpx → nuclei | An external surface you have to discover. Each stage feeds the next through the recon store: subfinder finds names, dnsx drops the ones that don't resolve, httpx finds what answers, nuclei scans what's live. |
| **Host Enumeration** | naabu → nmap → httpx | A scope you were given rather than one you found. These read the same scope rather than feeding each other; chaining them keeps three tools off the client's hosts at once. |

Host Enumeration is the pentest-shaped one, and it exists because the previous
single chain was not. `nmap` — the most pentest-relevant tool in the set — was
not in any pipeline at all.

Stages remain individually includable, and inclusion is now tracked per pipeline:
`httpx` appears in both chains, and excluding it from one must not touch the other.

### New tools

| Tool | Config | Yields |
|---|---|---|
| `dnsx` | `limit` (1–1000000), `timeout` (1–86400 s) | resolvable hosts → recon |
| `naabu` | `top_ports` (1–65535), `limit`, `timeout` | open ports → services |

Integer bounds mirror the ones VardrRunner enforces, so an out-of-range value is
refused at queue time rather than failing on the operator's machine after the job
has been claimed.

### VardrGate is deliberately still absent

`vardrgate_api_test` also has a working handler in VardrRunner, and it is the most
differentiated job type in the product family. It stays out of `_VALID_TOOLS`
because two pieces are missing here:

- **`POST /jobs/{id}/upload`** does not exist. The handler posts its sanitized
  result there and would 404.
- **No `test_case` model.** `VardrGateConfig` requires a structured object —
  request spec, identities, credential references — and VardrMap has no model,
  storage, or authoring UI for it. `_TOOL_CONFIG_KEYS` permits flat scalars only.

Adding it now would let an operator queue a job that cannot complete. Tracked in
`docs/implementation-roadmap.md` and pinned by a test so it fails loudly if
someone adds the tool without the endpoint.

### Tests

out-of-range and non-integer config rejected, unknown config keys rejected,
`vardrgate_api_test` still refused, and stage exclusions scoped per pipeline.
