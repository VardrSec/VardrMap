# v0.21.1 — 2026-08-08

## Unblock CI — dependency advisories, gitleaks licensing, TypeScript 7 deprecations

Every open pull request was unmergeable. None of the causes were in anyone's
branch: two of the three required checks had drifted red on `main` itself, which
had not run CI since 2026-07-23 and so never reported it.

### Frontend dependency advisories (blocking)

`npm audit --audit-level=high` failed on every PR — 2 critical, 3 high. Fixed by
upgrading, not by lowering the audit threshold:

- **`next-auth` `^5.0.0-beta.31` → `^5.0.0-beta.32`** — pulls `@auth/core` 0.41.3
  and clears all three criticals: `getToken()` uncaught exception on malformed
  headers (GHSA-xmf8-cvqr-rfgj), homoglyph `@` bypass in the email normaliser
  (GHSA-7rqj-j65f-68wh), and OAuth state/nonce/PKCE cookies not bound to the
  issuing provider (GHSA-x445-f3h2-j279).
- **`overrides.postcss` `^8.5.10` → `^8.5.26`** — clears the two sourceMappingURL
  path-traversal advisories (GHSA-r28c-9q8g-f849, GHSA-fxqj-rqcc-2cmp). The
  override is what makes this possible without `npm audit fix --force`, which
  wanted to drag `next` from 16.2.11 to 16.3.0 to reach the same patch.
- **`brace-expansion`, `js-yaml`, `dompurify`** — dev-tree transitives (eslint,
  jest, typescript-eslint), resolved in the lockfile only. No declared range moved.

`npm audit` now reports 0 vulnerabilities.

### Secret scanning (non-blocking, but dead since mid-July)

`gitleaks/gitleaks-action@v3` began demanding a paid `GITLEAKS_LICENSE` on
organisation repositories. Nothing in this repo changed — the floating `@v3` tag
moved under us, which is why runs from July pass and runs from August do not.

The gitleaks binary is MIT; only the Action wrapper is licensed. CI now installs
the release directly, pinned to **8.30.1** and verified against a recorded
SHA-256, then runs `gitleaks git . --redact`. No licence, and the tool can no
longer change without a commit here.

### TypeScript 7.0 deprecations

The Dependabot TypeScript bump surfaced `TS5101` on `baseUrl`. Both deprecations
are now removed rather than silenced with `ignoreDeprecations`, which only defers
the same failure to TypeScript 7.0:

- **`tsconfig.json`** — dropped `baseUrl: "."`. The `@/*` path mapping resolves
  relative to the config file's directory when `baseUrl` is absent, so it points
  at exactly the same place.
- **`tsconfig.test.json`** — `module`/`moduleResolution` `commonjs`/`node`
  (node10, deprecated) → `node16`/`node16`, which let `ignoreDeprecations: "6.0"`
  be deleted outright. `frontend/package.json` declares no `"type": "module"`, so
  `node16` still emits CommonJS and ts-jest is unaffected. All 71 tests pass.

### Not changed

- `overrides.sharp` stays. `next` 16.2.11 declares `sharp: ^0.34.5`; the override
  is the only thing holding the tree at 0.35.3, so removing it would walk the
  dependency back to the range v0.19.1 deliberately escaped.
- `Secret scanning` is still not a required status check on `main`. Making it one
  is a ruleset change, deliberately left as a separate decision.
