# v0.21.2 — 2026-08-08

## Type-check the test files, and fix the three fixtures that had drifted

The Dependabot bump to Next 16.3.0 (#29) failed its build on four type errors in
test files. The errors were not caused by that bump — they had been latent since
v0.14 and nothing in the pipeline was positioned to catch them:

- `next build` only type-checks what the application graph reaches, and no test
  file is imported by the app.
- ts-jest transpiles rather than type-checks, so `npm test` passed throughout.

Next 16.3.0 widens its build-time check to cover them, which is what surfaced the
drift. The fixtures were genuinely wrong; the tests only kept passing because
nothing verified them at the type level.

### Fixtures corrected

- `services_count` was added to `Program` in v0.14.0 (service discovery) but never
  added to the `Program` fixtures in `appReducer.test.ts`,
  `FindingsSection.test.tsx`, and `SubmissionsSection.test.tsx`.
- The `AUTH_LOADED` fixture in `appReducer.test.ts` still used the pre-NextAuth
  session shape `{ github_id, username, jwt }`, which has no properties in common
  with the current `AppSession` (`{ user: { githubId, username }, backendToken }`).
  The assertion is identity-based, so the reducer test passed against a shape the
  application has not produced since v0.3.

### Gate added

`npm run typecheck` (`tsc --noEmit`) now runs in the frontend CI job, between lint
and test. It covers everything in `tsconfig.json`'s `include`, test files among
them, so a fixture cannot silently drift from its type again.

This runs inside the existing **Frontend lint + build** job, which is already a
required status check — no ruleset change needed.
